Zig bindings for [[https://curl.haxx.se/libcurl/][libcurl]], a free and easy-to-use client-side URL transfer library.

This package supports the following Zig versions:
| Zig version | Branch |
|-------------+--------|
| =0.17=      | main   |
| =0.16=      | [[https://github.com/jiacai2050/zig-curl/tree/0.16][0.16]]   |
| =0.15=      | [[https://github.com/jiacai2050/zig-curl/tree/0.15][0.15]]   |

The vendored libraries consist of:
| Library | Version |
|---------+---------|
| libcurl | [[https://github.com/curl/curl/tree/curl-8_19_0][8.19.0]]   |
| zlib    | [[https://github.com/madler/zlib/tree/v1.3.1][1.3.1]]   |
| mbedtls | [[https://github.com/Mbed-TLS/mbedtls/tree/v3.6.0][3.6.0]]   |

* Usage
#+begin_src bash :results verbatim :exports results :wrap src zig
cat examples/basic.zig
#+end_src

#+RESULTS:
#+begin_src zig
const std = @import("std");
const curl = @import("curl");

const URL = "https://edgebin.liujiacai.net/anything";

pub fn main(init: std.process.Init) !void {
    var gpa: std.heap.SafeAllocator = .init(std.heap.page_allocator, .{});
    defer if (gpa.deinit() != .ok) @panic("leak");
    const allocator = gpa.allocator();

    var ca_bundle = try curl.allocCABundle(allocator, init.io);
    defer ca_bundle.deinit(allocator);
    var easy = try curl.Easy.init(.{
        .ca_bundle = ca_bundle,
    });
    defer easy.deinit();

    {
        std.debug.print("GET without body\n", .{});
        const resp = try easy.fetch(URL, .{});
        std.debug.print("Status code: {d}\n", .{resp.status_code});
    }

    {
        std.debug.print("\nGET with fixed buffer as body\n", .{});
        var buffer: [1024]u8 = undefined;
        var writer = std.Io.Writer.fixed(&buffer);
        const resp = try easy.fetch(URL, .{ .writer = &writer });
        std.debug.print("Status code: {d}\nBody: {s}\n", .{ resp.status_code, writer.buffered() });
    }
}
#+end_src

** std.Io integration
The request and response body APIs use Zig 0.17's =std.Io.Reader= and =std.Io.Writer= directly. libcurl still performs the transfer; the adapters synchronously read from or write to these interfaces in libcurl callbacks.

Pass a writer to =fetch= to receive a response body:
#+begin_src zig
var body = std.Io.Writer.Allocating.init(allocator);
defer body.deinit();

const response = try easy.fetch(URL, .{ .writer = &body.writer });
std.debug.print("Status: {d}\nBody: {s}\n", .{
    response.status_code,
    body.writer.buffered(),
});
#+end_src

For uploads, pass a reader and a writer for the response body to =upload=. A file reader needs the program's =init.io= context:
#+begin_src zig
var file_buffer: [4096]u8 = undefined;
const file = try std.Io.Dir.cwd().openFile(init.io, path, .{});
defer file.close(init.io);
var reader = file.reader(init.io, &file_buffer);

var response_body = std.Io.Writer.Allocating.init(allocator);
defer response_body.deinit();
const response = try easy.upload(URL, &reader.interface, &response_body.writer);
#+end_src

Use =init.io= with =curl.allocCABundle= as well when loading system certificates. For multipart parts, =MultiPart.NonCopyingData.ReaderBased= can avoid copying a large body, but the reader must remain valid until the transfer completes and its size must be known. These Reader/Writer adapters are synchronous: they do not make =Easy= or =Multi.poll= asynchronous or integrate curl with a Zig event loop.

** Diagnostics
When a curl operation fails, it returns a generic =error.Curl=. To get more detailed information, you can use the =diagnostics= field in =Easy= or =Multi=.

#+begin_src zig
    var easy = try curl.Easy.init(.{ ... });
    defer easy.deinit();

    easy.perform() catch |err| {
        if (err == error.Curl) {
            if (easy.diagnostics.getMessage()) |msg| {
                std.log.err("curl failed: {s}", .{msg});
            }
        }
        return err;
    };
#+end_src

** Asynchronous event-loop integration
=Easy.fetch= and =Easy.upload= are synchronous. =Multi.poll= also blocks while waiting for activity. For an event-loop-driven implementation, =AsyncMulti= exposes libcurl's multi-socket API without owning or blocking the event loop.

Create =AsyncMulti.Hooks= with socket and timer callbacks, then pass its stable address to =AsyncMulti.init=. The socket callback registers, updates, or removes readiness notifications; the timer callback schedules or cancels a timer (=timeout_ms == -1= cancels it). These callbacks must return promptly and must not call curl or block. From the event loop, call =socketReady= when a socket becomes readable or writable, and =timerExpired= when the timer fires. Drain =readInfo= to collect completed transfers.

The event-loop adapter is intentionally supplied by the application: it should translate its runtime's socket-readiness and timer facilities into these hooks. A callback returning nonzero aborts the current libcurl operation. Keep the hooks, easy handles, and callback context alive while registered; remove easy handles before destroying them. This interface does not make synchronous Reader/Writer callbacks asynchronous, and synchronous file or stream I/O inside those callbacks can still block the event-loop thread.

** Installation
#+begin_src bash
# Latest version
zig fetch --save git+https://github.com/jiacai2050/zig-curl.git
# Tagged version
zig fetch --save git+https://github.com/jiacai2050/zig-curl.git#v0.5.0
#+end_src

The latest tag can be found on [[https://github.com/jiacai2050/zig-curl/releases/][release page]].

After fetch, import =curl= like this in your =build.zig=:
#+begin_src zig
const dep_curl = b.dependency("curl", .{});
exe.root_module.addImport("curl", dep_curl.module("curl"));
exe.root_module.link_libc = true;
#+end_src

This library will link to a vendored libcurl by default, you can disable it and link to system-wide with this
#+begin_src zig
const dep_curl = b.dependency("curl", .{ .link_vendor = false });
exe.root_module.linkSystemLibrary("curl", .{});
exe.root_module.link_libc = true;
#+end_src
